# Anatomical bone display

Added October 6, 2026 to the canonical external-drive dashboard.

Body display → Anatomical bones enables a mixed anatomical mesh atlas (BodyParts3D with an OpenSim pelvis) for processed hitting and pitching recordings, including both handednesses. Meshes are fitted to the released joint centers; missing joints hide affected parts. The pelvis, ribs/scapulae/clavicles, cervical/lumbar spine, skull, humeri, radius/ulna pairs, femurs, tibia/fibula pairs, hands and feet use generic anatomical shapes. Skull and feet use raw markers when available. Transverse orientation, hands and shapes remain approximate.

The 1,055,724-byte binary atlas and about 9 KB metadata load only when the option is activated. These are fixed model assets; recordings are not preloaded. Disabling the option preserves the existing display, and switching trials disposes the previous GPU resources. The option remains off by default. The source dataset and scientific outputs are unchanged.

Validation: the 12 existing browser checks passed, plus eight bone-specific checks for on-demand assets, solo pitching/hitting, bone-only display, matched comparison, split view, movie preparation, left-handed fitting, missing samples and disposal. Seven extended checks passed, including Full body settings and a complete 78-frame H.264/yuv420p split-comparison movie with anatomical bones and floating charts at 60 fps. Three numerical unit tests and formatting checks passed.

Runtime mesh checksums, original element IDs and atlas checksum are in `assets/anatomy/bones.json`. Source and licensing are in `assets/anatomy/ATTRIBUTION.md`: BodyParts3D is CC Attribution 4.0 International and the replacement pelvis is Apache-2.0. The builder downloads the small OpenSim sources and notices at a pinned Git revision. The builder uses numpy and fast-simplification 0.1.13, with build-only requirements in `scripts/requirements-bones.txt`. Download the official archive to temporary storage, then run `python scripts/build_bones.py --archive /path/to/partof_BP3D_4.0_obj_99.zip`. The full atlas and build tool are not shipped as dashboard runtime dependencies.

## Pelvis replacement and fitting correction

On October 6, 2026, the oversized BodyParts3D pelvis was replaced with OpenSim GUI's `pelvis_l.vtp`, `pelvis_r.vtp`, and `sacrum.vtp` from its Curling lab geometry. Revision `2ceb01b476e7e1a9b40fd1dfbced6eabb17bb935` and individual source SHA-256 hashes are recorded in `bones.json`. The source surfaces receive one Loop subdivision pass and a coordinate conversion. OpenSim's Apache-2.0 license and original NOTICE are included. All other bone-part geometry remains unchanged.

The earlier atlas normalized outer pelvis width to approximately 1.65 times the approximated femur-proximal spacing; fitting to the released hip centers exaggerated the displayed pelvis. The replacement normalizes its **outer width** to one, so the renderer's existing uniform scale makes that width equal to released hip spacing. This is an intentional generic display convention, not a claim that measured hip-center spacing equals anatomical pelvis breadth. Position, orientation and limb anchors still follow the same released landmarks. No angles, forces, timestamps, or joint-center trajectories are changed.

Driveline's [pipeline article](https://drivelinebaseball.com/blogs/blog/a-look-under-the-hood-how-driveline-sport-science-collects-processes-and-analyzes-thousands-of-athletes-biomechanics-data) confirms Visual3D use; its [hitting article](https://drivelinebaseball.com/blogs/blog/introduction-to-hitting-biomechanics) includes skeleton animations. Their appearance is consistent with Visual3D graphics, but the exact mesh source and redistribution permission were not established. HAS-Motion documents [replaceable graphic models](https://wiki.has-motion.com/doku.php?id=visual3d%3Atutorials%3Amodeling%3Abuilding_a_6_dof_model_-_segment_properties) and [two common pelvis graphics associated with CODA and Helen Hayes](https://www.wiki.has-motion.com/doku.php?id=visual3d%3Adocumentation%3Amodeling%3Asegments%3Asegment_overview). These pelvis definitions and display meshes should not be confused with the released scientific model.
