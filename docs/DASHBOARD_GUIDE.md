# OpenBiomechanics Motion Lab

A local dashboard for exploring the downloaded [OpenBiomechanics Project](https://github.com/drivelineresearch/openbiomechanics) pitching, hitting, and high-performance releases. This repository root is the working source; `OBM_DATA_ROOT` points to an independent upstream checkout without moving or modifying its data.

## Start

Follow [the repository setup instructions](../README.md). From the repository root, with your virtual environment active:

```sh
export OBM_DATA_ROOT=/path/to/openbiomechanics
python server.py
```

Open **http://127.0.0.1:8766/**. Stop with Ctrl-C; use `--port 8767` for another port. The first run builds local `cache/csv_spans.json` and `catalog.json`; later starts reuse them. CSV changes invalidate the indexes. After adding or replacing C3Ds, use `--refresh-catalog`. `python server.py --build-index` reports catalog counts without starting the server. Run `python scripts/build_data.py` to regenerate the ignored JSON required for assessments, cohort bands, and limb estimates.

The interface has a pitching/hitting selector, searchable trial list, motion viewer, play/pause, looping, frame stepping, event jumps, synchronized plots, live readings, and collapsible trial details. Drag in the viewer to orbit, scroll to zoom, and right-drag to pan. **Plane views** beside the camera selector toggles three small, synchronized XY, YZ, and XZ orthographic views in the viewer's upper right. They frame the current skeleton pose closely, including all selected skeletons in comparison mode, while showing the same enabled trails, force plates, and other scene layers as the main view. Space toggles playback when focus is outside an input or button. Move near a colored event marker on the replay timeline to reveal its label; click either the marker or its popup to jump to the event. Drag across any plot to scrub the replay; plots, motion, forces, and the transport share one playhead. The side panels collapse from buttons inside their headers. The visible layer buttons below the viewer control the single-replay display; **Focus in 3D** remains above the viewer. The replay bar uses a single draggable playhead and contextual event popups.

**Key charts** starts with twelve pitching views or nine hitting views when processed signals exist. Pitching begins with the two joint-position views from the reference report, a five-curve kinematic sequencing view, and the same velocity chain zoomed from foot plant (100% body weight) to release. The arm-position curves are elbow flexion, shoulder external rotation, shoulder abduction, shoulder horizontal abduction, and wrist extension. The lower-body curves are pelvis and torso axial rotation, their published relative separation, lateral trunk tilt, and lead-knee flexion. The velocity chain is pelvis and torso axial rotation, elbow extension, arm internal rotation, and lead-knee extension. All are drawn from released `joint_angles.csv` or `joint_velos.csv`; shoulder abduction and the three extension/internal velocity traces have their signs reversed to match the screenshot labels. The original pitching charts follow these four views. Hitting includes the estimated sweet-spot path elevation and the published lead-leg force components alongside bat speed and the other mechanics charts. You can remove, reorder, or widen key charts; **Reset** restores the defaults available for that trial. **Full Set of Time Series Data** is collapsed by default in a full-width panel. Its **Expand** control or the **Full data ↓** shortcut beside Reset opens every released full-signal column, one CSV file at a time, followed by published-trace comparisons, dashboard calculations, and raw C3D channels. **Add to key charts** pins any plot above the tabs. Repeated event-time fields are event markers rather than flat signals; trial keys and time columns serve as identifiers and axes. POI CSVs contain one value per trial, so they appear in Details. Each plot shows its source, units, event markers, live value, and shared playhead. The dashboard keeps the native 360 Hz motion and 1,080 Hz force timestamps rather than joining them by rounded time.

The interface uses a neutral control palette, with red for replay progress, blue for selection, and green for enabled layers and the solo-view force plate arrows. These accents take their cue from [RYBitten](https://rybitten.space/#editormake); restrained spacing and hierarchy follow [Nielsen Norman Group’s visual-design principles](https://www.nngroup.com/articles/principles-visual-design/).

The Sessions **Filters** button expands availability, handedness, pitch type, playing level, sorting, and metric-range controls. Pitching metric choices include velocity, shoulder external rotation, elbow varus moment, pelvis/torso rotation speed, and peak lead ground-reaction force; hitting includes exit velocity, bat speed, attack angle, and pelvis/torso rotation speed. These numeric filters use released trial-level POI/metadata values; raw-only recordings have no POI fields and are omitted when a POI metric is selected. The dashboard uses locally bundled Inter throughout. Colored replay ticks reveal event popups when you hover near them or focus a marker; both the tick and popup jump to that time. In **At playhead**, a missing sample is displayed as a dash; a measured zero remains zero.

The Sessions **Browse by** control switches between the existing **Files** list and **Athletes**. Select an athlete to open their pitches or swings; calibration files appear in a separate subsection, and **← All athletes** returns to the athlete list. Search, filters, and sorting apply in either view. Processed trials use the released metadata `user` ID. For raw-only recordings and static models, the dashboard reads `USERid` from the C3D filename as documented by the repository.

## Explore keypoints

**Explore keypoints** opens anatomical hotspots in the solo 3D replay. It is off by default. The **Point size** slider beside **Show** starts at 50% of the original marker diameter and can go to 0% to hide all hotspots while keeping the selected chart open. **Essentials** shows a short list centered on the trunk, pelvis, throwing/lead arm, lead knee, lead foot, and, for hitters, the bat sweet spot. **Joints and motion** adds other joint centers; **Forces and power** exposes processed ground reaction force near the feet, individual C3D force plate vectors at the plates, and, for pitching, modeled joint moments and power; **Raw C3D markers** exposes measured marker positions plus calculated marker speed and a noise-sensitive acceleration diagnostic. The raw layer is opt-in because its many markers would obscure the stick figure. A raw-only recording offers raw markers and measured plate vectors; processed-only swings offer the released landmark and model signals that exist for them.

Click a hotspot, then choose a signal in its compact chart. The chart uses that signal's native timestamps, labels time in seconds and the vertical axis in its unit, and has a cursor synchronized with playback. Drag across it to scrub the replay. The selected hotspot stays highlighted and follows the anatomical point as the athlete and camera move. The chart remains in a fixed screen position; drag its title bar to move it, or drag its lower-right corner to resize it. Closing the chart deselects its signal and removes its 3D focus guide. **Pitch/Swing Details** shows the current value, exact file and column, whether it is raw, published, or calculated here, and the definition. Position entries are from `landmarks.csv` unless the selected layer is a raw C3D marker; modeled angles, velocities, moments, and energy terms retain the released values. The colored hotspot is a display anchor, not evidence that a force or power is physically measured at that point.

Where an angle has an existing **Focus in 3D** guide, selecting it shows colored rays or a wedge without changing the camera in its default Free mode. The guide is constructed from displayed joint centers and may differ from the published anatomical angle. A pitching joint-power selection offers a spatial color map; the map shows signed generation/absorption or the published transfer term at modeled joint locations. Elbow varus moment can enable the arm sweep, bat speed can enable the bat-speed sweep, and an individual plate hotspot can reveal its measured force arrow. These displays do not infer an anatomical direction of energy flow or animate energy traveling toward the ball. The hitting release has no `energy_flow.csv` or joint-moment full-signal table, so those choices do not appear for swings. With **Info boxes in MP4** checked, floating keypoint charts are included as clean plot panels at their saved positions and sizes. Their selected signals, replay colors, live values, units, event lines and playheads update throughout the video; window controls, source notes and descriptions are omitted. Charts in the row below the viewer are outside the export area.

**Torso rotation** draws arrows and a shaded angle at the reconstructed trunk center. Its blue arrow is the zero reference (side-on for pitching, lab +X for hitting) and its amber arrow is the chest-facing direction estimated as perpendicular to the line between the shoulder joint centers; the shaded wedge lies between them. The pitching side-on reference follows the observed released pelvis-angle zero; for hitting, +X points toward the mound. **Torso–pelvis separation** places a similar angle guide near the lower trunk, with the blue arrow derived from the hip line and the amber arrow from the shoulder line. Both guides update with the pose through the recording. Their wedge sizes are signed joint-center geometry; these are display locations, not physical joint pivots. The chart and keypoint value still use the released, signed `joint_angles.csv` model components `torso_angle_z` and `torso_pelvis_angle_z`, so the guide may differ from the number. Both are available from **Focus in 3D** and **Explore keypoints**; comparison replays also offer both guides per skeleton.

The workflow draws on [OpenSim's selectable 3D model objects and plotter](https://opensimconfluence.atlassian.net/wiki/spaces/OpenSim/pages/53090508/New%2BFeatures%2Bin%2BOpenSim%2B3.0) and [AnyBody's selected-output chart view](https://anyscript.org/tutorials/Interface_features/lesson3.html). The dashboard keeps the chart close to the selected anatomy and states the release source beside each result.

## Scap load in the viewer

For pitching, **Focus in 3D → Scap load · horizontal abduction** frames the throwing shoulder from above. The live number is the released `joint_angles.csv: shoulder_angle_x` (positive horizontal abduction; negative adduction). The **Scap load · shoulder horizontal abduction** chart is an optional single-trace plot under **Full Set of Time Series Data → Comparisons**. The same released signal is also available in the `joint_angles.csv` tab. Its peak is the published POI `max_shoulder_horizontal_abduction`.

The orange transverse-plane wedge is a separate pose guide: in the torso transverse plane, it shades the angle between (1) the shoulder line extended outward from the throwing shoulder and (2) the throwing shoulder-to-elbow vector. That geometric angle preserves its direction and can differ from the published model-based anatomical angle. The released data do not directly isolate scapular-blade retraction; “scap load” is the common shorthand for this shoulder horizontal-abduction proxy. The [official pitching conventions](https://github.com/drivelineresearch/openbiomechanics/blob/main/baseball_pitching/README.md) define its sign. Driveline [describes the proxy](https://drivelinebaseball.com/blogs/blog/interpret-biomechanics-reports) and [shows an overhead example](https://drivelinebaseball.com/blogs/blog/leveraging-assessment-data-build-throwing-programming).

## Pitching skeleton color map

In a processed pitching replay, select **Color skeleton** below the 3D viewer and choose a **Metric**. **Body display** controls the skeleton and raw markers; clicking outside either display menu, moving keyboard focus outside it, or pressing Escape closes it; **Scene display** controls trails, plates, force plate vectors, and the decoy ball. The `(i)` in the color legend explains the current metric and scale.

| View | Source and calculation | Placement and interpretation |
| --- | --- | --- |
| Joint generation / absorption (default) | `energy_flow.csv`, `*_energy_generated`, as released | Joint center; **negative blue = absorption**, **positive red = generation**. The title word order does not set the sign order. |
| Joint-force transfer power | `energy_flow.csv`, `*_energy_transfer_jfp`, as released | Joint center; signed value, without an asserted transfer direction. |
| Segment-torque transfer power | `energy_flow.csv`, `*_energy_transfer_stp`, as released | Joint center; signed value, without an asserted transfer direction. |
| Net joint work since peak knee height | Dashboard trapezoidal integral of `*_energy_generated` | Joint center; cumulative net work (J), which differs from released event-window POI totals. |
| Segment-endpoint power | `energy_flow.csv`, 22 published `*_seg_pwr` columns | A short sleeve at each modeled proximal or distal segment end; signed power, not a flow arrow. Pelvis and thorax placements are schematic. |
| Joint moment magnitude | `forces_moments.csv`, vector magnitude of published x/y/z components | Joint center; N·m. Green → yellow → red uses the same colors as the elbow-varus arm sweep, with zero → half → full color limit. Hip and shoulder use the distal thigh/upper-arm reference. This is not direct ligament load. |
| Angular velocity magnitude | `joint_velos.csv`, vector magnitude of published x/y/z components | Joint center; °/s. Pelvis and torso use calculated geometric center positions. |
| Ground reaction force magnitude | `force_plate.csv`, vector magnitude of processed rear/lead x/y/z ground reaction force | Near the corresponding ankle; N. This represents the foot-level signal, not force at the ankle joint. |
| Vertical ground reaction force | `force_plate.csv`, rear/lead `force_z` as released | Near the corresponding ankle; signed N, with positive upward. |

The overlay uses reconstructed positions from `landmarks.csv`. Each joint or plate value is shown at its nearest anatomical location, with a colored 28%-length sleeve along an adjacent segment for visibility. This is a **display mapping**, not a measurement of power, moment, or force throughout the bone. The 22 endpoint powers use short sleeves at the modeled end of their segment and no joint dots; multiple endpoint measures can share a joint location. An endpoint power is the model's mechanical power term at one end of a segment; its sign alone does not establish direction of energy transfer through that segment. The pelvis/thorax endpoint markers are schematic. All modes use the nearest sample on their **own native timeline**: 360 Hz for energy and joint signals; 1080 Hz for force-plate signals. Missing values are light gray.

The default color scale is fixed within a replay and metric, using the 90th percentile of absolute values across all mapped locations after peak knee height for pitching and across the full recording for hitting. The legend's `(i)` panel offers an optional **Scale each location separately** switch, off by default. When on, every mapped joint, segment end, or plate location uses its own 90th percentile over time; the legend changes to percentages because equally colored locations may then represent different absolute values. Signed modes span negative blue to positive red through yellow zero. Joint moment magnitude uses green → yellow → red; the other magnitude modes span yellow zero to red. Values beyond the limit saturate **only in color**; readout numbers are unchanged. At the start or end of a replay, the color and readout hold that signal's first or last valid sample if its source timeline starts later or ends earlier; missing values inside the signal remain missing. Cumulative work is an exception to edge holding: it remains unavailable before its PKH origin and after any missing integration interval, since the unknown work cannot be treated as zero. The released data arrays are not altered. The color map is available in solo replays with processed landmarks and the required signal. Turning it off restores the normal skeleton colors.

The full-signal README names the energy-flow fields but does not explicitly state their units. We label the instantaneous traces **W** because they integrate to the released joule POI quantities: for example, the positive throwing-elbow `energy_generated` trace for pitch `1031_2` from FP to BR integrates to approximately **7.08 J**, matching its `elbow_generation_fp_br = 7.0827 J`. Net work is therefore labeled **J** and is a dashboard calculation, not a released per-frame energy trace. For the two transfer modes, blue and red show the **signed published number**; the release does not document a sign convention sufficient to equate either color with a confirmed anatomical direction of transfer. The overlay does not measure muscle metabolism, stored segment energy, ball energy, or energy delivered to the ball. The released POI energy totals integrate different event windows for front and rear joints, so the optional PKH-to-playhead net-work view is not identical to those POI totals. See the [official pitching table schema](https://github.com/drivelineresearch/openbiomechanics/blob/main/baseball_pitching/README.md) and [joint-power/transfer methods in pitching research](https://pmc.ncbi.nlm.nih.gov/articles/PMC9532595/).

The moment and angular-velocity color views are dashboard **magnitudes derived from published component traces**. The ground-force magnitude is derived likewise, while vertical force is a released component. The energy-flow columns and segment-endpoint powers are released traces, and only net work is integrated in the dashboard. Position-derived hand or center-of-mass speed is not used in this map.

## Hitting bat sweep and skeleton color map

In a processed swing, **Scene display → Bat sweep · speed** draws a translucent surface between released `blast_hand` and `sweet_spot` positions through the playhead. Colors use a **color-only Gaussian filter** of native reconstructed speed (σ = 12 ms, support ±36 ms). Positive weights suppress rapid sampling ripples without overshoot; the filter never crosses missing data or timestamp gaps. Colors interpolate continuously from green to yellow to red on an **mph scale**, then return through yellow to green as the bat slows. Green is retained through the filtered 40th percentile from foot contact onward; red saturates at the filtered 95th percentile; yellow is the speed halfway between those bounds. The legend starts at 0 mph and shows the midpoint and red saturation speed in mph, and its current value is explicitly filtered. All supported frames from foot contact onward are drawn, including the slowest speeds in green; there is no low-speed visibility cutoff. This is a visual treatment only: right-side reconstructed speed, speed charts and published reference values retain the native unfiltered derivative. The blue dot identifies the released sweet spot.

**Color skeleton** offers the hitting views below. Lead and rear map to anatomical left/right according to the released hitter side (`R`: lead left; `L`: lead right). Colored dots mark joint centers and short sleeves mark nearby segments; the values do not measure force or motion continuously along a bone.

| View | Source and calculation | Placement |
| --- | --- | --- |
| Joint angular speed | Magnitude of the released x/y/z components in `joint_velos.csv` (°/s) | Lead/rear knee, hip, shoulder, elbow, wrist; pelvis and torso at schematic centers |
| Joint-center linear speed | Three-point derivative of released `landmarks.csv` XYZ positions, then magnitude (m/s) | Same locations; pelvis and torso use midpoints of the two hip and two thorax landmarks |
| Ground reaction force magnitude | Magnitude of the released rear/lead x/y/z traces in `force_plate.csv` (N) | Near the corresponding rear/lead ankle |
| Vertical ground reaction force | Released rear/lead `force_z` in `force_plate.csv` (signed N; positive upward) | Near the corresponding rear/lead ankle |

The hitting release contains `joint_angles.csv`, `joint_velos.csv`, `landmarks.csv`, and `force_plate.csv`, but no hitting `energy_flow.csv` or `forces_moments.csv`. The viewer therefore does not offer hitting joint power, joint work, energy-transfer, or joint-moment coloring. Its force colors show **ground** reaction force at the feet; measured 3D force arrows still use the C3D platforms when available. These overlays are for solo processed swings; raw-only swings have no matching processed color signal.

## HitTrax contact and outcome data

The released `baseball_hitting/data/poi/hittrax.csv` contains one row for **604 of 677** processed swings. It is a per-swing table, not a frame-by-frame ball trace. The **Contact and outcome** section in Swing Details now shows HitTrax launch angle, spray bearing, estimated carry, predicted result, incoming pitch speed and descent, plus a fixed-scale pitch-location diagram. The red dot plots `horizontal_distance` and `vertical_distance` in inches from the strike-zone center; positive horizontal is defined by HitTrax as inside to a right-handed batter. The diagram is an offset chart, not a measured strike-zone outline. A zero incoming-pitch speed is shown as unavailable, since the table contains 51 zero-speed rows; it is not treated as a measured stationary pitch. The original fields remain in the collapsed **HitTrax** disclosure, including `strike_zone` and `poi_x/y/z`. The release does not specify units for the `poi_*` coordinates, so they are not placed in the 3D lab scene.

**Scene display → HitTrax launch direction** optionally adds a short purple ray after contact. It starts at the reconstructed bat sweet spot at the published contact time and points according to HitTrax launch angle `la` and spray bearing `bearing`. The guide uses the hitting lab convention (+X toward the mound, +Y toward the right-handed box, +Z upward), with vector `(cos la cos bearing, −cos la sin bearing, sin la)`. Its **fixed 1.6 m length is only for visibility**; it does not show measured carry, ball speed, spin, drag, or a tracked flight path. The anchor comes from `landmarks.csv`, not from a calibrated HitTrax-to-motion coordinate registration. It appears only when the swing has both linked HitTrax angles and processed contact landmarks. When **Fake ball** is also enabled, the arrow is replaced by a ball moving along that same direction and a growing purple tube from the contact anchor. Travel uses the published exit velocity and stops extending at 7 m for readability. It is a straight launch illustration, without measured trajectory, spin, drag or gravity. Disabling the ball restores the fixed arrow; disabling HitTrax removes the tube and restores the standard illustrative ball animation. Scrubbing backward shrinks the tube and removes it before contact.

## Compare replays

Select a pitch or swing, then choose **Compare replays** in Sessions. Click up to three more recordings in the Files or Athletes list to overlay them. The button is also the way back to the unchanged solo view. Comparisons stay within pitching or within hitting because the releases use different lab-axis conventions. Static calibration files are excluded. A selected row has a colored check; click it again to remove that replay. **Use as reference** switches which recording owns the playback timeline and event ticks.

**Split panes** beside **Sync at** and **Position** switches the comparison viewer from the default overlay to one pane per replay. It works for both pitches and swings, including their per-replay bat/trail, marker, plate, force-vector, and focus settings. Each pane has its own orbit, pan, and zoom controls; playback, event alignment, and chart playhead remain shared. The panes start at a common physical scale, but independent zooming can change that scale. **Reset camera** reframes them. The small XY/YZ/XZ plane views are temporarily hidden while the split grid is open.

Each replay gets one hue—red, blue, green, or purple—across its body, nearby-shade trail, markers, force plate arrows, chart curves, and detail card. Each card has **Body display** and **Scene display** menus for independently showing thick segments, thin skeleton, joint centers, raw markers, hand/bat path, the colored bat-speed sweep (or pitching arm-moment sweep), force-plate outlines, force plate vectors, and the illustrative ball. Sweeps use the same geometry and color filtering as the solo viewer, grow through each replay’s aligned playhead, and work in overlaid or separate views. Hitting cards show their own mph color scale when the sweep is enabled. Missing required signals disable that replay’s sweep option. Menus close on click-away or Escape; toggling a layer keeps its menu open. Unavailable layers are disabled. The default is the body and trail, plus joint centers when published landmarks exist or raw markers when they do not; forces and ball remain optional. In the charts, curves from the same replay keep its hue; dashes distinguish multiple measurements within a chart. Click a curve's legend entry to hide or restore it. Plot dragging still moves the shared playhead. The right panel shows compact trial summaries and live angle and force readings for each selected replay. Swing comparisons use the same native sweet-spot derivative as the solo chart and readout, with published speed summaries labelled separately.

The playback bar spans the full union of the aligned recordings, including time before or after the reference recording. When one replay has not started or has already ended, its skeleton stays at the first or last usable pose with the most complete available set of segments. This also covers recordings whose final timestamp contains missing joint points. Its hand/bat trail stays at the corresponding boundary (empty before the start, complete after the end), and its card says **Held at start** or **Held at end**. Available force plate arrows hold their last valid sample too. These held visuals are display padding, not extra measurements: charts stop at the last recorded sample, and live metrics show a dash outside the recorded interval. Trails remain visible at the final frame of both solo and comparison playback.

Each replay card has an independent **Focus in 3D** selector for its torso, shoulder, elbow, lead knee, or rear knee, plus the additional pitching positions and speeds from the report views. Selecting a quantity adds that replay's colored joint guide and a live value beneath its selector; it does not move, rotate, or zoom the shared camera. You can show different guides on multiple skeletons at once. **Whole motion** clears only that replay's guide; **Reset camera** changes the camera view while leaving the selected guides visible. Elbow and knee flexion wedges use the angle between the distal segment and the proximal segment extended through the joint, so a straight joint is 0°. Shoulder and trunk wedges are pose guides formed from available joint centers and lab directions; the per-replay readout displays the released CSV value separately. Focus uses released joint-center landmarks, so raw-only C3Ds do not offer these anatomical options.

**Explore keypoints** on a replay card is off by default. Turn it on to click that replay's anatomical hotspots in the shared view or its own split pane. Selected signals open separate, resizable charts side by side beneath the 3D viewer; dragging a chart scrubs the synchronized comparison. **Charts in viewer** moves those charts into the 3D viewer, with each chart placed inside its own pane when split views are active. Drag a chart's title to move it and its corner to resize it; its position stays fixed while the skeleton moves. Each replay controls its own hotspot group and point size. **Match settings** copies body and scene display choices, color and trail metrics, keypoint visibility/group/size, and the selected keypoint and signal—including its 3D angle guide—to the other replays. It matches corresponding anatomical signals across handedness; missing signals are left unselected. Identity colors and cameras stay per replay. **Snap all to view** copies pane cameras. Axial-rotation guides show arrows and a shaded angle without a circular backdrop.

**Sync at** defaults to the published ball-release event for pitches or bat-contact event for swings. Foot contact, foot plant, recording start, and equal percentage of recording duration are also available. The primary recording's time remains on the transport and chart x-axes; each other recording is sampled at its own aligned time. If a selected event is absent for one replay, that replay uses its recording start as the anchor, and its card says so. Replays outside their recorded time range hold their boundary pose in the viewer and show no live sample.

**Position → Align pelvis** translates each replay in XYZ so its pelvis midpoint at the selected sync time matches the primary replay. This makes body motion easier to compare; translated force plates move with that replay and should be read as relative spatial context. **Lab coordinates** uses the released XYZ positions and actual plate geometry without translation. Neither choice rotates or rescales the motion. The same comparison can include different athletes; color identifies the replay rather than an athlete across sessions. For linked and processed-only recordings, the bodies use released joint-center landmarks. Raw-only recordings use the available C3D markers and their approximate marker connections.

The interface uses a light theme. If the browser cannot create a WebGL context, the catalog and plots still load and the motion panel switches to a 2D projection with playback. For the full 3D view, use a browser with WebGL enabled. If an older page remains open after an update, reload it.

The separate **High Performance** release is an assessment-level table at [`high_performance/data/hp_obp.csv`](../openbiomechanics/high_performance/data/hp_obp.csv), not a collection of per-assessment replays. It has 1,934 rows and 53 columns, including CMJ, squat jump, repeated hop, isometric mid-thigh pull, plyo pushup, shoulder strength/ROM, and some pitch/bat-speed summaries. The released high-performance folder has no corresponding trial C3Ds, full-signal time series, or POI folder. Its `athlete_uid` does not have a published crosswalk to the pitching/hitting athlete IDs, so these rows cannot be safely attached to the motion replays. The separate computer-vision collection contains a few sample movement C3Ds (including a CMJ), but they are not recordings for the high-performance table rows.

The **High Performance** dashboard tab starts with the selected athlete's ID, playing level, body weight, assessment count, and latest assessment date. The release has no athlete names or height field, so the header does not invent either. Pitch or bat speed, its distribution, and session history come next, ahead of the assessment profile and other charts. Switch among dated assessments with the selector above the profile. Eight profile bars are shown first; expand **Other released measures** to see percentile bars for the other 38 numeric columns. Missing measurements show a dash. The measure menu also exposes all 46 numeric columns for charting. The other seven columns are identifiers, dates, or grouping fields. All released assessment values remain available through the right panel, including fields whose physical units were not documented.

The left rail has **All**, **Pitchers**, and **Hitters** toggles. An athlete qualifies for pitching or hitting when an assessment row at the chosen playing level contains a corresponding session date or speed; an athlete can qualify for both. Choosing Pitchers or Hitters switches the speed charts to that modality. **Filters** uses the same layout as the replay browser: assessment-test availability, **Sort by**, **Order**, playing level, and a numeric **Metric range**. Sort by assessment date, athlete ID, number of assessments, or any released numeric measure; missing sort values go last. The range filter uses each athlete's latest available numeric result at the selected level. These filters apply to the athlete list, peer distributions, percentiles, and scatterplot correlations. ID search narrows only the athlete list for navigation. With **All playing levels**, reference plots still compare the selected athlete with athletes at that athlete's level. **Clear filters** restores the full cohort.

The source table contains four `pitch_speed_mph = 0` rows belonging to three athlete IDs: `2f966a91-bdb4-4be3-8da1-14c6fe8b4b78` (two rows), `d5188d2c-35a6-44ea-beed-83b17d772779` (one), and `e70278af-2e67-4f6e-88fd-2d2870f7c633` (one). Because a zero-mph pitch speed is not credible and each athlete also has nonzero records, the dashboard quarantines **all assessment rows for those three athletes** from the profile, distributions, history charts, percentiles, test coverage, summaries, and scatterplot calculations. They remain in the unchanged CSV and dashboard data snapshot. The left athlete list shows them after all normal entries under **Excluded from analysis**, each with a red **ERR** tag. Flagging is computed from the loaded table, so a refreshed snapshot will be screened the same way.

The right sidebar repeats the eight main assessment percentile bars above Test coverage for quick reference. It uses the exact same bars and filtered peer cohort as the main profile; the additional 38 measures remain available in the main profile.

The speed section appears above the general measure explorer. It shows a same-level pitch- or bat-speed distribution and the selected athlete's speed results over **session dates** (not assessment dates), with duplicate date/value records suppressed. The selected speed histogram marker uses that athlete's latest available session result. The general distribution compares each athlete's latest available test result at the selected playing level. History charts plot the selected athlete's measurements against a gold 25th–75th peer band and median line from the same latest-per-athlete distribution. These guides are **not** date-matched historical percentiles.

The scatterplot's **X axis** menu independently selects any released numeric measure to compare with the pitch- or bat-speed field. Each dot uses one athlete's latest row with both values. The selected athlete has a red dot when a paired result exists. Hover for the values and a remove action, or restore removed dots with the button above the chart. Small `r` and `R²` labels appear inside the plot. Removing a dot changes only the current browser view and its displayed sample size, correlations, and optional least-squares line; it never edits the source CSV. Session speed can have a different measurement date from the physical assessment. Missing results remain missing.

The browser reads [`data/high_performance.json`](../data/high_performance.json), a compact snapshot generated directly from the released CSV. Refresh it after changing the local CSV with `python scripts/build_data.py --only high-performance` from the repository root. This writes only inside `data/`.

## Reading the chart layers

| Layer in the dashboard | Where it comes from | How to use it |
| --- | --- | --- |
| Raw recordings | C3D points and plate analog channels | Inspect measured marker positions, gaps, plate channels, and calibration clips. A marker is not automatically a joint center. |
| Calculated landmarks | Released `landmarks.csv` | Replay published joint centers and bat endpoints; these are the points used to draw the stick figure. |
| Published mechanics | Released joint angles, velocities, forces, moments, and energy flow | Inspect the pipeline's anatomical definitions and native time traces. |
| Comparisons | Multiple published traces placed on one chart | Compare timing and shape in the same published unit. |
| Calculated here | This dashboard's vector magnitudes and derivatives | Inspect a local estimate; consult its chart note for the formula and limits. |
| POI | Released trial-level tables | Read single-value summaries such as peak speeds or release/contact metrics. |

The hitting release provides contact and maximum bat speed as scalar POIs, but no bat-speed time series. The original three-point derivative of released `sweet_spot_x/y/z` amplified repeating short/long source-position increments into speed ripples. The same increment pattern is visible in raw C3D bat markers for the verification trial. Native CSV timestamp rounding adds smaller numerical jitter; the exact source/export cause of the repeating steps is unresolved. A 1 ms timestamp truncation hypothesis helped swing 103_1 but worsened many other trials, so it is not applied.

The headline **Reconstructed bat speed** is now the magnitude of the **unfiltered three-point derivative** of released `sweet_spot_x/y/z`, evaluated at the **released CSV timestamps**. It does not snap timestamps to a nominal sampling grid, smooth the headline curve, choose a fitted bat point, rescale speeds, use contact/peak anchors or impose a monotonic profile. Missing samples and recording endpoints remain missing when derivative support is insufficient. Published POI values and contact events do not affect the computed signal. Native differentiation may retain ripples from the source positions; the dashboard reports those values without correction.

The separate smoothed XYZ chart remains an optional diagnostic. It never drives the right-side reconstructed readout, primary speed chart or comparison readout. Trail coloring has its own independent Gaussian visual filter. Published contact and maximum speeds appear only as references and can disagree with the native reconstruction.

The GitHub hitting README and CSV data dictionary define `bat_speed_mph_contact_x` as resultant contact speed, `sweet_spot_velo_mph_contact_{x,y,z}` as sweet-spot velocity components, and `bat_speed_mph_max_x` as maximum resultant speed. Across all 677 POI rows, the component magnitude differs from contact speed by a mean 0.135 mph (maximum 0.424 mph), supporting the sweet spot as the intended reference, with small remaining differences in released summaries. `blast_bat_speed_mph_x` is separately measured by the Blast sensor. The documented 40 Hz Butterworth filter concerns ground reaction force, not bat velocity; it is not used as evidence of a bat filter.

The right-side live reading, comparison live reading, speed chart all use the native **Reconstructed bat speed**. Published contact and peak values remain separate summary references; the chart shows peak as a dashed line with unknown timing, contact as a circle and Blast sensor contact as a cross. The blue dot identifies the released sweet spot. Independent smoothed XYZ speed, raw derivative and cylinder midpoint speed remain separate diagnostic charts. Trail coloring uses a separate filtered native-speed copy, with continuous colors and an mph legend as described above.


**Shared trail scale** in the comparison toolbar is off by default. Off: each replay uses its own trail scale. On: every selected supported sweep uses the same observed minimum and maximum over the complete displayed sweep phases (filtered native bat speed for hitting; released elbow moment for pitching). Green/yellow/red map to the shared minimum/midpoint/maximum, so equal values produce equal colors across replays. Selection changes recompute the range; playhead changes and individual visibility toggles do not. Each enabled card displays its active scale in mph or N·m. Switching the scale recolors geometry without changing poses or speed signals.

Comparison force vectors always use a **shared maximum resultant force magnitude**, across all plates and all frames of every selected replay, regardless of individual force-layer visibility. Arrow length = 1.8 m × instantaneous magnitude / selected maximum. Equal magnitudes therefore have equal lengths across people; the scale is fixed during playback and recalculated when selection changes. This is a visual length normalization, not bodyweight normalization; force values remain in newtons.

Split-pane cameras stay fixed during playback and scrubbing. Initial framing and explicit camera resets fit the full recorded delivery and every force-plate corner, with 55 cm of horizontal padding and 35 cm of vertical padding plus a 12% camera margin. All panes use the same fitted distance for consistent visual scale; each pane retains independent manual orbit, pan and zoom. Playback never recenters the camera or its orbit target on the athlete.

Time-series cards can be resized by dragging either side, the bottom edge or a bottom corner. Widths snap to a fine 24-track grid; neighboring cards reflow as space changes. Canvas plots redraw at their new dimensions, while playhead dragging remains on the plot itself. Resize-handle arrow keys also adjust width/height. The per-card reset-size button (or double-clicking a handle) restores the default size; the existing key-chart Reset restores the full default layout. Sizes are retained per recording while the dashboard stays open, including when switching between solo and comparison views. Source-library charts support the same controls.

In comparison Separate views, each athlete card has **Snap all to view** beside Scene display. Orbit, zoom or pan that athlete’s pane, then click its button to copy the camera view to all currently visible panes. Pan is applied relative to each athlete’s full-motion framing center so each replay remains centered consistently. Cameras remain independent after the snap and stay fixed during playback.

Each comparison athlete’s Body display menu includes **Color skeleton**, in both overlay and split-pane views. Its independent metric selector includes only available signals: pitching power/work, moments, angular velocity and foot ground reaction force; hitting angular speed, joint-center speed and foot ground reaction force. These use the same signal calculations, colors and 90th-percentile scale definitions as solo viewing. A per-athlete option scales each location separately; legends and live values retain the physical units and distinguish published signals from calculations. Missing values are gray. All camera, trail, body/scene controls and resizable charts apply to both disciplines.

Pitching arm trails have an independent **Arm trail metric** selector in the solo Scene display menu and each comparison athlete card. Varus is max(0, elbow_moment_y); valgus is max(0, −elbow_moment_y), following the released internal-moment convention (varus +Y, valgus −Y). Opposite-direction frames stay green and the complete sweep is retained. This is not a relabeling of internal varus as an external valgus load. Scales recompute on metric changes, including Shared trail scale, without resetting cameras. Bat trails are unchanged. Comparison sidebar cards show published session height and weight near velocity, in feet/inches and pounds with metric equivalents underneath. **More athlete & recording info** expands age, playing level, handedness, athlete/session IDs, pitch type or available bat specifications, and data availability. This works for pitching and hitting; missing measurements show a dash. Pitching metadata uses meters/kg and hitting metadata uses inches/pounds, converted only for display.

**Save MP4** snapshots the current cameras, body/scene layers, skeleton metrics, trail metrics, alignment, sync, solo/overlay/split layout, viewer size, playback speed and selected floating keypoint signals/windows. **Info boxes in MP4** is off by default: the saved video contains the 3D scene and its enabled visual layers, without the title, metric legend boxes or playback-time label. Check it before saving to include those boxes and any visible floating keypoint charts. Each chart keeps its saved position and size; the exported panel contains the replay title, selected signal, live value, units and synchronized curve/playhead, without dropdowns, buttons or descriptive notes. This works for solo, shared comparison and split-pane pitching/hitting views. The plot uses the same chart renderer as the live dashboard. This option changes only the exported video; the live viewer keeps its legends. The local server renders the complete replay at exactly 60 fps in an isolated background browser and writes a standard H.264/yuv420p MP4 with a finalized sample index and fast-start metadata. This doubles the sampled frames versus the earlier 30 fps export, so rendering can take longer and files can be larger. This avoids fragmented MediaRecorder files that QuickTime cannot trim. **Limb lengths → Estimates** appears in the right sidebar for solo and comparison replays in both disciplines. ## Keypoint angle geometry audit (October 1, 2026)

Shoulder external rotation uses `joint_angles.csv · shoulder_angle_z`, unchanged. It is axial rotation of the humerus relative to the thorax, not the angle between the upper arm and forearm. The previous wedge incorrectly used projected trunk-up as zero. The corrected geometric zero is perpendicular to projected trunk-up and the humeral axis, in the plane normal to the shoulder–elbow line. The projected forearm is the moving ray. The wedge is translated along the humeral axis to the elbow so that the forearm shows the rotation; the highlighted shoulder and shoulder–elbow line identify the joint and axis. Left and right arms use mirrored references. It hides when the projected forearm or reference is too small to define the angle.

This remains a **joint-center pose guide**, not a recalculation of Visual3D's calibrated segment frames. For pitch `2760_1` at 1.300 s, the old guide was 22.1°, the corrected guide is 112.1°, and the released model value is 104.5°. The renderer no longer folds signed rotation into an unsigned acute angle. When shoulder rotation passes 180°, the released angle selects the continuous branch of the geometric angle; it does not set the wedge size. The same geometry implementation is used in solo, overlay, split panes, and MP4 export, including the hitting lead shoulder.

Elbow and knee guides retain 0° for a straight limb. Their joint-center bends can approximate rather than exactly match the released model, especially at the hip/knee. Torso rotation, pelvis rotation, separation, horizontal abduction and trunk tilt now retain the geometric rotation direction. Torso/hip heading guides use the displayed landmarks and zero references; trunk tilt and horizontal abduction use body-oriented planes, not the complete ordered model rotations. Wrist extension has no wedge: elbow, wrist and hand centers alone cannot distinguish wrist flexion/extension from radial/ulnar deviation without the calibrated forearm and hand frames. Its numeric trace remains available.

Definitions: [released pitching signs](https://github.com/drivelineresearch/openbiomechanics/blob/main/baseball_pitching/README.md#kinematics-joint-angles-joint-velocities), [Visual3D shoulder pipeline](https://github.com/drivelineresearch/openbiomechanics/blob/main/baseball_pitching/code/v3d/CMO.v3s), [Visual3D shoulder rotation conventions](https://has-motion.com/wiki/doku.php?id=visual3d:documentation:visual3d_signal_types:link_model_based_data_type:joint_angle:shoulder_cardan_sequence). The source pipeline computes the humerus relative to the thorax; its calibrated frames and ordered rotations are why a joint-center drawing is an approximation.

The audit also found a source-convention discrepancy: the pitching README lists positive shoulder Y as adduction, while the released positive Y values agree with positive `shoulder_abduction_fp` in the POI data (e.g. pitch `2760_1`, approximately 83° at foot plant). The focus readout, report chart and report table now show shoulder Y without the previous negation. No source arrays are changed; the optional component plot is labeled **Shoulder Y angle** to avoid claiming that the conflicting sign documentation is resolved.
