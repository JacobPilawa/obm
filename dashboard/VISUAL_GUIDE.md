# Motion visuals and floating charts — 2026-10-02

Use **Body display** in the main viewer or in each comparison card. All five motion overlays are optional and start off. Processed pitching and hitting trials support them; raw/model-only recordings without the required processed signals disable them.

- **Center of mass:** amber sphere matching the joint-center nodules, using released `centerofmass_x/y/z` in metres. Its keypoint chart reports targetward COM X velocity from the native three-point position derivative. This is the released model's COM estimate, not a new anthropometric estimate.
- **COM trail:** cumulative path up to the current time, independently switchable. Scrubbing backward shortens the path; missing samples/time gaps are not bridged.
- **Trunk axis · geometric guide:** purple hip-midpoint → shoulder-midpoint line, extended toward the floor and above the shoulders. A dashed vertical reference makes inclination visible. Only the main purple axis and the gray reference are drawn; history lines and spatial labels are removed. Axis inclination remains available as a keypoint trace. A near-horizontal trunk suppresses the unstable floor intersection. This describes trunk orientation; it is neither an instantaneous rotation axis nor whole-body angular momentum, and its movement is not a validated stability score.
- **Lead-leg braking / force X:** a signed horizontal ground-reaction-force arrow anchored at the lead ankle's floor projection. It is not a measured center of pressure. Pitching released lead-force X is posterior-positive, so its sign is reversed into targetward-positive lab X; hitting force X already uses targetward-positive lab X. Cyan means the force opposes COM X motion; brown means it aids motion or direction alone can be described. Below 0.05 m/s the direction classification is withheld. The label uses body weights when mass is known (N otherwise); arrow length is 0.45 m/BW, capped at 1.8 m (fallback 0.00045 m/N). This is one leg and one force component, not net whole-body braking, impulse, joint power, or an efficiency score.
- **Lead-knee extension:** highlighted hip–knee–ankle segments and a geometric knee arc. Green indicates extension; orange indicates flexion. Extension rate is the negative of the released flexion-velocity component. The numeric knee angle is the published model angle; the joint-center arc is a spatial guide and is not substituted for that angle.

COM, trunk-axis inclination, knee extension, and signed lead force also have keypoint traces and buttons to enable their spatial visuals. No new smoothing is applied.

## Floating plots

Choose **Explore keypoints → Show: Full body**, then check any combination of charts. Pitching offers the four requested charts: throwing-arm kinematics, torso/lower-body kinematics, sequencing, and the foot-plant-to-release angular-velocity chain. Hitting offers its existing axial angles, knee flexion, rotation sequence, and upper-chain speeds. Both disciplines also offer a COM targetward-velocity chart; clicking the COM keypoint selects velocity first. Signals, units, signs, and colors come from the same chart definitions used below the viewer. A single compact legend above each floating chart has clickable entries to hide/show individual lines; each entry has a live value in a fixed-width slot with tabular digits, so changing numbers do not change the legend wrapping. The duplicate canvas legend is suppressed.

Drag a window by its header, resize with the visible corner handle (or its arrow keys), close it or uncheck its box, and drag across its chart to scrub playback. Arrow keys/Home/End work when a full-body chart has keyboard focus. Full-body windows remain available when switching keypoint categories; disabling Explore keypoints hides them. Comparison windows use their own trial's local time and follow split-pane bounds.

Every single-keypoint and full-body floating plot now has **Start** and **End** selectors. Choose signal endpoints or the actual released events: PKH, FC, FP, MER, BR, MIR for pitching; FC, FP, contact for hitting. Only available events appear. Invalid order retains the previous valid window and displays an explanation. Full-body angular-velocity-chain charts initially use FP→BR. More-key-moment lines are independently switchable.

Movie snapshots retain the overlay choices and floating chart selections/ranges. Floating charts appear in exported movies when **Include info boxes** is enabled. Export code paths were checked; no video was rendered during this update.

## Peer percentile bands

The **Peer bands · 25–75%** button updates the bottom time-series plots, single-keypoint charts, full-body floating charts, comparison plots, and exported chart panels. It starts off. The default is **Same playing level**, within the current discipline; choose **All playing levels** to widen the group. These cohorts are independent of sidebar filters. The caption shows cohort athlete/trial counts. Each comparison trial uses its own discipline and playing level.

Bands use exactly the dashboard's existing processed/derived signal definitions. They are aligned to pitching BR or hitting contact in actual seconds, sampled every 10 ms from 3 seconds before to 1 second after that event. The current trial's event time places this grid on the plot; event/phase display modes transform the resulting x coordinates. Native selected-trial traces are unchanged. The cohort is release/contact aligned even when an x-axis uses phase percentages; peers are not individually phase-warped.

At each grid point, supported trials are averaged within athlete, then the 25th/75th percentiles are calculated across athlete averages using linear quantile interpolation. Thus athletes with more released attempts do not dominate the band. The selected athlete is included. Bands have low opacity and match each line's color. Hiding a line also hides its band. Bands are a descriptive interquartile range, not a confidence interval or normative target. At least five supported athletes are required at every timepoint; missing support splits the band. Counts can vary across time and signal. The hitting independent cohort has four athletes, so its band is withheld; choose all levels if appropriate.

Source totals are 411 pitches / 100 athletes and 677 swings / 98 athletes. Raw C3D-only signals and static POI reference lines do not receive a processed-peer waveform band. Cached assets are loaded once when enabled; regenerate them after changing source data or signal definitions with `build_cohorts.py` using the volume Python environment and Node. This uses the same JS chart/keypoint definitions and does not load C3D motion. It streams trials into athlete accumulators and writes `data/cohort_pitching.json` and `data/cohort_hitting.json`.

The peak COM–pitch-velocity scatter plot and its data/statistics/script are in `../reproductions/misc/com_velocity/` relative to the biomech root's dashboard. It uses the released peak targetward COM velocity POI. See that folder's README for interpretation.

## Research ideas worth discussing

1. **Pelvis–torso coordination loops:** plot pelvis rotation against torso rotation, with a moving time cursor and phase coloring. This would reveal how the two segments move together rather than just the gap between peak speeds. Wang et al. use angle–angle plots and coordination analysis in pitching. The dashboard has suitable published angles, but event definitions and coordinate conventions must remain explicit; the paper uses IMUs and different FC detection. Suggested next addition, not implemented here. [Wang et al., 2025](https://journals.sagepub.com/doi/full/10.1177/23259671251350302).
2. **Event-aligned cohort bands:** overlay the selected trial on an explicitly defined cohort mean/dispersion for COM velocity, lead-knee extension, pelvis/torso velocity, and elbow moment. Driveline's full-signal analysis illustrates why the shape and timing of a curve matter beyond its peak. Preserve actual seconds alongside any normalized phase axis and display sample/athlete counts; avoid treating observational differences as causal. The initial percentile-band comparison is now implemented; more flexible filter-defined cohorts remain a possible extension. [Driveline full-signal analyses](https://drivelinebaseball.com/blogs/blog/full-signal-analyses-the-next-step-in-biomechanical-analysis).
3. **A synchronized lead-leg-block panel:** combine the new spatial force arrow with COM X velocity, signed force/BW, knee angle, and extension rate over FC→BR/contact. Much of this information already exists individually; the useful addition is a coordinated view and clearly specified phase impulse, rather than another decorative trail. Driveline compares lead-leg force components and knee measures, and shows that accounting for body weight changes associations. Suggested combined view; no new impulse calculation has been added. [Driveline lead-leg-block analysis](https://drivelinebaseball.com/blogs/blog/a-quantitative-analysis-of-the-lead-leg-block-and-its-contributions-to-velocity).

Your existing elbow-moment sweep, bat-speed sweep, and joint-power overlays already cover several useful spatial encodings. The strongest remaining opportunities are coordinated timing, cohort context, and pelvis–torso coordination—not simply more colored trails.
